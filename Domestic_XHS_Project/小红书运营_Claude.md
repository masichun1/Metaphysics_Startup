
# 小红书运营 — OpenCLI × Claude 自动化工作流

## 业务目标与IP定位
国内小红书玄学赛道自动化运营。
- 业务目标：国内小红书玄学赛道自动化运营。
- 人群画像：高净值人群（具备高消费能力、高认知水平，追求精神富足与文化底蕴）。
- 变现路径：通过文化与玄学内容建立极高信任度，后续精准导流至独立的“高端文创用品”垂直账号。
- 四大内容合集矩阵：
  - 合集 1 严格引证道家经典文献原话，用严谨的逻辑降维拆解四柱八字与五行生克，为受众提供高阶运势分析与商业/人生决策参考。
  - 合集 2 碎碎念：展示主理人的商业洞察、生活哲学、修心日常，打造高维陪伴者人设。
  - 合集 3 传统文化：赏析传统器物、非遗工艺、东方美学，为文创用品做品味铺垫。
  - 合集 4 中医养生：深度分析中药材配方及香氛/物件置于日常身边的实际益处，结合时令节气与道家养生功法，输出高质感的日常保养心得。

## IP 人设规范（强制遵循）

### 人设定位
当代创业者，白天有别的事在忙。某天突然觉得——灵魂该歇一歇了。不是修行，不是出家，就是想让自己慢下来。开始翻老书，道藏、易经、内经。不是专家，也不装。就是读到有意思的记下来，翻译成不费劲的人话。不教你暴富，不让你转运。更新不多，也不营业。是一个突然想通了的人，偶尔出来透透气。

### 语气铁律
| 规则 | 说明 |
|------|------|
| **网感口语** | "就是说""谁懂""不是我就想问"——年轻人的说话方式，不写书面语。遇到有共鸣的可以"这个我熟"，但不说"卧槽"——人设是有底蕴的，不靠惊叹号表现情绪 |
| **淡淡的不讨好** | "不保证更新频率""不保证每篇你都爱看""偶尔什么也不聊"——不营业不焦虑不画饼 |
| **短句呼吸感** | 一句话不超过 20 字。句号换行。一段不超过 4 行。给读者呼吸的空间。 |
| **谦虚不装** | 是"在读在学在琢磨"的人，不是专家。用"翻到""读到""有点意思"开头，不用"我知道""我早就"。不炫耀知识量，不列书单 |
| **作家的文笔** | 每一句都经过锤炼。能删的字全删。名词精准，动词有画面感。节奏有快有慢——短句利落，长句有呼吸。读出声是舒服的 |
| **不矫情** | 不感叹人生，不升华主题，不"原来这就是成长"。观点到了，收住。情绪让读者自己品，不替读者感动 |
| **点到为止** | 给观点不给结论。读者自己悟。不说"所以你应该……" |
| **不堆术语** | 引经典立刻用白话翻译。不写"夫""矣""也"。不装。 |

### 风格参照：灶生（必须模仿）

**灶生是谁：** 一个把道教活成日常的人。做雷击枣木圣杯、去抱朴道院看师兄、拍丧葬乐队电影、北漂租房改风水。不是"玄学博主"——是一个在实践的人，偶尔记两笔。

**灶生的写法（14篇笔记分析）：**

| 特征 | 说明 | 示例 |
|------|------|------|
| **白描不渲染** | 发生了什么就写什么。不加感叹，不升华意义 | "来抱朴道院看师兄""今天是祖师香" |
| **行动驱动** | 每篇都是做了什么、在做什么、打算做什么。不是"想了什么" | "打算用雷击枣木做些Mini圣杯""雨后灵山寻雷击木" |
| **不说教不科普** | 从不解释"什么是雷击木""什么是圣杯"。懂的人自然懂，不懂的也不讨好 | 标题带"雷击木打假"但不展开讲原理 |
| **日常化神圣** | 祖师香、土地公公、灶神——这些在灶生笔下跟"今天去了趟超市"一样自然。神圣的事不端着写 | "等待土地公公回家" |
| **系列感** | 内容有连续性——(一)(上)01，像在追一件事。不是每篇独立选题 | "北漂风水师租房改造日记 01""雨后灵山寻雷击木（上）" |
| **第一人称在场** | 永远是"我""我们"。不是观察者，是当事人 | "关于我们开始做丧葬乐队的故事" |
| **短标题，直给** | 不超过20字。不用钩子，不设悬念。就是告诉你这篇写了什么 | "来抱朴道院看师兄""打算用雷击枣木做些Mini圣杯" |

**灶生的核心：他不是在"做内容"。他在过一种生活，顺便记下来。**

### 写作结构（参照灶生微调）
```
白描标题（≤20字，做了什么就写什么）
↓
行动/场景开篇（我在哪，在干什么——不铺垫不渲染）
↓
一个细节展开（看到了什么、摸到了什么、闻到了什么）
↓
收住。不总结。不升华。走了。
```

### 禁忌
- 禁止：算命、风水、转运、开光、招财、作法、灵验（触发平台迷信检测）
- 禁止：最好、第一、100%、绝对、保证（广告极限词）
- 禁止："点赞关注""评论区告诉我""私信我"（引流诱导）
- 禁止：长篇大论、清单式展开、教程式输出（不像人）
- 禁止：emoji 刷屏（最多 1 个）

## 架构逻辑
采用 **"OpenCLI 作为四肢/眼睛，Claude 作为大脑"** 的闭环架构：

- **OpenCLI** 负责读取、监控网页和调研竞品，并将生数据传回给 Claude。
- **Claude** 负责分析数据、制定策略，生成新的执行脚本或话术，发回给 OpenCLI 去自动执行。

## 核心开发任务（Skills）

### Skill 01 — 数据自动追踪

- **目标**：定时抓取指定关键词或对标账号的数据表现。
- **数据维度**：笔记点赞数、收藏数、评论数、分享数、粉丝增长趋势、发布时间、文案字数、标签使用。
- **技术实现**：OpenCLI 定时爬取搜索结果页/个人主页，结构化存储至本地数据库或 CSV，Claude 分析趋势并输出优化建议。

### Skill 02 — 评论区监控
- **目标**：实时分析评论区情绪，提取高频问题或潜在客户意向线索。
- **数据维度**：评论情感倾向（正面/负面/中性）、高频关键词、用户提问聚类、竞品评论区导流信号。
- **技术实现**：OpenCLI 爬取指定笔记的评论列表，Claude 进行 NLP 情感分析和意图识别，输出潜在客户名单与应对话术。

### Skill 03 — 竞品/同行调研
- **目标**：爬取并拆解爆款图文的结构、文案逻辑和标签。
- **数据维度**：标题公式、封面风格、正文结构、互动话术、标签组合、发布时间规律、评论区运营策略。
- **技术实现**：OpenCLI 爬取对标账号/话题下的高互动笔记，Claude 逆向拆解爆款公式，生成本号可复用的内容模板。

### Skill 04 — 新号冷启动辅助
- **目标**：生成高点击率的起号选题库和文案框架。
- **核心策略**：
  - 基于 Skill 03 的竞品分析结果，提炼当前赛道的爆款选题方向。
  - 结合玄学赛道特性（神秘感、情感共鸣、实用性），生成差异化选题。
  - 提供多版本文案框架（悬念型、干货型、情感型、争议型），适配不同内容风格测试。
- **技术实现**：Claude 基于竞品数据生成选题库和文案模板，OpenCLI 可辅助批量创建草稿笔记。

### Skill 05 — 引导关注
- **目标**：根据不同场景，生成自然且高转化的引流话术策略。
- **场景覆盖**：
  - 评论区互动 → 引导关注话术
  - 私信回复 → 粉丝转化话术
  - 笔记结尾 CTA → 关注/收藏引导
  - 直播话术 → 实时互动转化
- **技术实现**：Claude 生成多版本话术库，OpenCLI 辅助自动回复（需谨慎控制频率，避免触发风控）。

- Skill 06 违禁词与风控检测（GitHub 调取）：通过 OpenCLI 定期在 GitHub 上搜索、调取并更新最新的“小红书违禁词/敏感词库”。在生成任何最终文案前，强制调用该词库进行比对过滤，确保账号安全。

## 安全红线

小红书平台风控极严，所有 OpenCLI 脚本的架构与设计必须将“反爬虫检测”与“防封号机制”置于最高优先级：

| 防护维度 | 具体措施 |
|---------|---------|
| **浏览器模拟** | 使用 Playwright 模拟真人操作：鼠标轨迹、滚动行为、打字节奏 |
| **指纹伪装** | 指纹浏览器（Browser Fingerprint 伪装），Canvas/WebGL/Audio 指纹随机化 |
| **时序控制** | 随机休眠间隔（500ms-5s 不等），避免固定频率触发风控 |
| **IP 策略** | 代理 IP 池轮换，单 IP 每日请求上限控制 |
| **会话管理** | Cookie 与 Session 持久化管理，模拟正常用户登录态 |
| **熔断机制** | 请求频率实时监控，触发验证码/异常响应时自动降级暂停 |
| **账号隔离** | 一机一号一 IP，
账号间操作完全隔离 |
